# Colorado county map geometry

The county directory map uses `src/site/colorado-county-map.json`, a static,
simplified SVG geometry asset. Its 64 records retain five-digit Colorado FIPS
strings and are joined to county names from the public county registry. FIPS
routes are generated by the existing `path("counties", fips)` helper. The
geometry is bundled locally; the site does not fetch map data, tiles, or
geocoding services at runtime.

## Source and reuse basis

- Publisher: Colorado Department of Transportation (CDOT).
- Dataset: [Counties in Colorado](https://data.colorado.gov/Transportation/Counties-in-Colorado/ahgn-r8s5), Socrata ID `ahgn-r8s5`.
- The dataset's Licensing and Attribution metadata lists **Public Domain**;
  checked November 14, 2026. The source record describes the 64 boundaries as
  produced by CDOT. This note records the catalog's stated license and does not
  make a separate legal interpretation.
- The simplified SVG geometry is adapted from Beta-1's checked-in derived map
  at commit `c85f64e9fc420d8b309a844ac5596e4aadb9db13`. No Beta-1 application
  code, county records, or unsupported counts are copied.
- Attribution is retained in the page caption: “Source: Colorado Department of
  Transportation.”
- The shapes are for illustrative navigation only; they are not legal or
  surveying boundaries.

The asset metadata and upstream source hash are recorded in
`src/site/colorado-county-map-source.json`. Geometry validation checks all 64
records, unique five-digit FIPS values, county-name slugs, valid SVG paths and
the viewBox. It also requires exact agreement with the Beta-2 public registry.

## County identity and fail-closed behavior

The original seed had reversed two county names. Additive migration
`0015_correct_lake_la_plata_county_names.sql` corrects the registry without
changing FIPS keys or historical migration files. The canonical identities are
`08065` Lake and `08067` La Plata, as confirmed by both the CDOT data and the
Census Bureau fixture at `tests/fixtures/colorado-counties-acs26.json`.

Before rendering, `validateCountyMap` requires 64 unique five-digit FIPS values,
one matching registry entry and county-name slug per region, valid closed SVG
paths, and exact 64-county coverage. If a check fails, the renderer emits only a
short fallback message; the searchable text directory remains available. It
never guesses a county identity or creates interactive links from a mismatched
registry. This check runs during page rendering and is covered by regression
tests for reversed names, incomplete registries and malformed geometry.

The map and directory use the same server-normalized search results. The
progressive enhancement updates the visible directory, map highlights, result
count, and `q` URL state together. Clearing the filter removes `q`; direct URL
loads and browser history navigation restore the corresponding filter. County
groups are sorted by normalized display name, with FIPS as a deterministic tie
breaker.

The complete text directory remains usable when the map is unavailable or a
county is difficult to select visually. Map anchors use the canonical FIPS
routes. No map-library or external map-service dependency was added.
